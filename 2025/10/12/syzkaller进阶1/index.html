syzkaller进阶(一)

崩溃报告

crash介绍

当 syzkaller 找到一个崩溃程序时，它将信息保存在 workdir/crashes 目录中。
该目录对于每种不同的崩溃类型有一个单独的子目录。
每个子目录包含一个 description 文件，包含用于识别崩溃的唯一字符串（用于漏洞识别和去重）；
以及最多100对 logN 和 reportN 文件，每一个测试机器的崩溃对应一对文件：

crash log

crash log（崩溃日志） 是记录内核崩溃事件的关键文件,包含原始的 syzkaller 日志，包括内核控制台输出以及崩溃前执行的程序。

  • 1.触发崩溃的完整系统调用序列（syz 格式）、崩溃上下文，是潜在种子素材
  • 2.syzkaller 的 syz-executor 主动记录
  • 3.结构化格式
  • 4.会带有一些内核打印日志
  • 5.这些日志可以提供给 syz-repro 工具进行崩溃定位和最小化，或者提供给 syz-execprog 工具进行手动定位

crash report

文件包含经过处理和符号化的内核崩溃报告（例如，KASAN 报告）

我们通常只需要这一对文件（如 log0 和 report0）中的一个，因为它们可能描述相同的内核错误。然而，syzkaller 最多保存100对这样的文件。

特殊的crash

遇到以下这几种崩溃时，大概率看不到 reportN 文件，因为测试机器没有输出，就没有东西可放入报告中，有时这些崩溃表明 syzkaller 本身存在错误

  • no output from test machine ：测试机器根本没有输出
  • lost connection to test machine ：与机器的 SSH 连接意外关闭
  • test machine is not executing programs ：机器看起来是活着的，但在很长一段时间内未执行任何测试程序

syz-repro

poc介绍

POC（Proof of Concept，概念验证） 是一段段能够验证某个漏洞、功能或理论可行性的代码、脚本或步骤集合。它的核心作用是 “证明某个问题确实存在，且可被复现”，是漏洞分析、功能验证和技术演示的关键工具。通常为c代码

syz-repro介绍

syz-repro 是 syzkaller 工具链里的复现器，拿到一次 crash（或任意 syscall 序列）后，它会在本地 QEMU/VM 里反复执行、最小化、并尝试生成稳定可触发 panic 的精简用例，最终输出两种形式的 PoC：

  • 1.Syz 格式——用 syzkaller DSL 描述的最短系统调用序列
  • 2.C 格式——把同一序列翻译成可编译运行的 C 程序，方便在没有 syzkaller 的环境下调试。

syz-repro的使用

使用syz-repro对log中包含的prog进行复现，这个流程包括

  • 1.提取出可以触发crash的初始prog
  • 2.对这个prog进行简化，基本采用的是逐个syscall削减简化
  • 3.对prog的参数等进行简化
  • 4.将prog转化为C poc
  • 5.对C poc进行简化

执行命令后，等待亿段时间即可结束，最后就可以看到

程序最小化

  • 1.初始状态的log包含大量冗余调用的原始序列
  • 2.syz-repro 会通过 “逐步剔除 + 验证崩溃” 的迭代过程，找到最小化序列
    • 首先从log的原始调用中，标记出与崩溃上下文相关的 “高嫌疑调用”
    • 采用 “二分法” 逐步删除低嫌疑调用，并验证剩余序列是否仍能触发崩溃
    • 当序列简化到只剩少量调用时，进行 “单调用剔除验证”
    • 稳定性验证，需要经过多轮重复执行
  • 最终输出的最小化程序

syz-prog2c的介绍

syz-prog2c 是 syzkaller 工具链中的一个实用工具，主要功能是将 syzkaller 生成的 .syz 格式程序（包含系统调用序列的结构化测试用例）转换为 C 语言代码

syz-execprog

syz-execprog的介绍

syz-execprog 是 syzkaller 工具链中用于执行 .syz 格式测试用例的核心工具，主要负责将 syzkaller 生成的系统调用序列（测试程序）在目标环境中实际运行，并捕获执行过程中的内核行为（如崩溃、异常）。它是连接 “抽象测试用例” 与 “实际内核执行” 的关键组件。

  1. 解析 .syz 文本 → 内部 Prog 对象
  2. 通过 IPC 把程序发给 syz-executor
  3. 收集结果、统计、crash 信息。

syz-execprog的使用

可以使用 syz-execprog 工具在循环模式下执行崩溃日志中的所有程序，以检查其中是否有导致内核崩溃的程序。然后，可以通过测试每个单独的程序来确定哪一个导致了崩溃：syz-execprog 是在本地执行程序的，所以你需要将 syz-execprog 和 syz-executor 复制到使用测试内核的虚拟机中并在那里运行9p共享反正失败了，不知道为什么
