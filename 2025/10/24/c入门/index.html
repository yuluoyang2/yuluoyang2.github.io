关键字

  • sizeof 关键字

    sizeof(x) 在编译时计算并确定出x在内存中所占字节数

    是关键字 常被误解为函数

    x 可以是变量 常量 类型 函数

  • char

    最小数据类型，也是最适合操作硬件的数据类型

    ASCII ： 表示字符空间

  • int

    最适合CPU的数据类型，系统⼀个周期内所能接受的最大处理单位就是int 一般为4byte，大小跟编译器有关

  • short/long

    本质是修饰int的,是默认情况下省略int。

    short 2 bytes long 8 bytes

  • signed/unsigned

    signed代表有符号数,通常省略。unsigned为无符号数

  • float/double

    浮点类型，即可以表示小数,float he double 不能直接判断是否相等

    判断相等通常需要人为取一个精度

  • void

    ⼀般void⽤于函数占位符、void*

    • 函数占位符我也不知道干什么，大家都这样
    • void* 表示数据空间，接受任意大小的数据

  • struct

    感觉没什么好说的，重点还是字节对齐,默认4字节对齐

    可以使用__attribute__((packed))关键字，不需要做字节对齐（按照一字节对齐）可能有用吧

  • union

    联合体,内存表现为：共享⼀份内存(以最大数据类型作为分配空间)和内存的首地址

    联合体+结构体可以设计数据包

  • enum

    懂得都懂

  • typedef

    是给数据类型起⼀个别名，让程序的可读性更⾼,常用用法如下

  • auto

  • register

    register关键字是⼀个建议性关键字。想要定义的变量放到cpu的寄存器中,但是一般很难做到，寄存器的值不能使用&取地址了

  • static

    C++和C的static有些区别

    • 作用域：全局变量/函数前一般是当前源文件有效extern无法修饰
    • 生存周期：整个程序生存期

  • extern

    extern⽤来声明⼀个没有被static修饰的变量或者函数。

    extern “C”，⽤C++的编译器按照C的规则进⾏编译。C++和C在编译规则上有很多不
    同，所以在C++中想完全复用C写的代码，就可以使用extern”C”来修饰，在C++使用C的lib库的
    时候比较常见

    以后更新还有很多不熟的地方，但是自己也没怎么用过，理解也不是很深刻

  • const

    准确的理解应该是read only，可以修饰变量和指针
    近水楼台先得月

    const设计的初衷就是为了代替宏，消除它的缺点，继承它的优点

  • volatile

    volatile关键字常用于避免编译器优化，主要用于处理硬件寄存器、中断服务程序和多线程等情况，
    如果有地方读取buff的值的时候，都需要从内存中读取

    示例如下，可以去掉volatile尝试一下，并且开启O3优化，看看效果

    gcc volatile.c -o volatile -lpthread #需要链接线程库

  • goto

    常用于驱动开发(个人理解)，有点汇编跳转的感觉

运算符

  • <<左移

    在没有溢出之前，每移动⼀位等价于乘于2，且移位后右边补0

  • >>右移

    每移动⼀位等价于除于2。signed类型和unsigned在右移的时候有差别：如s果是负数，移位后补1，正数补0，所以负数通过右移永远都不会等于0

  • &

  • ~

    清零器

  • |

    置位器

C与面向对象

C语言是面向过程的语言，但我们可以借助C++等语言的面向对象思想，实现类似”继承”、”多态”、”封装”、”重载”的功能。从而服务于架构设计内核源码。

C与继承

利用结构体来实现继承，c++里面的成员变量就是c的结构体变量，c++的成员函数就是c的结构体指针，但是c在实例化的时候需要进行初始化(变量赋值，函数指针绑定)

C与封装

将抽象的数据和行为（或者方法）相结合，形成⼀个有机的整体。是⾯向对象思想的核心，目的是增强安全性和简化编程，使用者不必理解具体的实现细节，通过调用接口操作数据成员。

C与多态

通过父类的指针来调用子类中的方法。作用是把不同的子类对象当做父类来
看，屏蔽不同子类之间的差异，用于适应需求的不断变化，本质上是面向抽象编程

  • 先放个实例，我也没完全理解，以后更新
  • linux设备驱动模型-多态
    • 派生类里放基类
      device_driver是内核统一管理的基类,子系统platform把自己的函数表包在上一层,形成派生类
    • 注册过程
      注册时内核只接收&drv->driver,不关心具体是platform还是i2c
      内核通用层只认识device_driver::probe(struct device *),
      所以没有直接存platform_driver::probe,而是套了一层函数platform_drv_probe 通过driver的probe最终调⽤到platform_driver的probe
    • 回调函数
      回调的核心特征是调用权转移，你写，别人决定何时调用。
      函数地址 注册给外部实体，调用语句写在外部实体里，你不主动调用它，而是等它被触发
      不是自己亲自调用
